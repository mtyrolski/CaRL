## Annotation and evaluation

For a training fragment, show Codex a blinded packet with its ID, domain, public task goal, start and original end observations, and the typed domain vocabulary. Codex proposes structured effects and preservation conditions or abstains. Verify that every effect is unmet at the start and holds at the original endpoint. Check preservation from the start through the earliest verified hit and retain the original endpoint in the evaluator audit. Keep complete replay evidence separate from the generator's model-facing rows. These labels describe partial predicate intents. Treat exact-state targets as a distinct task. Demonstration labels in `D_A` have missing scale. Preserve Codex provenance and every raw response.

An authorised collection extension freezes new membership before its rollouts. Bind it to the original split hash, preserve the original split files, and reject world or chain overlap with the withheld cohorts. The Prompt 03 Craftax support extension uses this procedure.

For controller measurements, freeze the candidate types and IDs before sampling. Start every attempt from the same simulator snapshot and initial controller memory, with deterministic independent seeds, a fixed action cap and an unchanged controller. Retain first-hit duration, task success, violations, unknowns, terminal setting and cost separately. Use the weighted midrank of successful durations in each context for the policy-relative (u), with weights proportional to the measured success fractions. Keep failed and incomplete attempts in the audit. Compare demonstration-only, measured without scale and measured with scale using matched pairs, resources and tuning budgets.

Measure first-hit duration from the restored checkpoint in executed primitive actions. A dispatched primitive that leaves the observation unchanged still counts. A Craftax request overridden by a sleeping or resting tick is recorded as a request and as automatic native work. Preserve separate counters for decisions, role calls, requested actions, executed primitives and automatic ticks. Check required preservation before acting and at every native tick boundary. Missing intermediate evidence yields an unknown preservation result unless an observed state already establishes a violation. Restore policy memory with the checkpoint. Changing the Craftax future transition key leaves the starting physical state fixed and is independent of the policy seed.

Report task success and intent progress separately. Count all simulator decisions and model calls, including warm-up, invalid/no-op actions, speculative branches, failures and retries. Report preparation and inference costs separately. Checkpointing, prompt selection and stopping decisions use the declared validation split. Open the sealed group only for the matched final evaluation. Treat the public integration fixtures as plumbing results.

The local direct validation uses the same frozen starts and action contract per domain for each model. A decision carries one to four named primitive actions and may include a short intent. The runner checks the task, preservation and limits after each native transition. An interruption drops the rest of the batch. The next decision sees the new public observation, its previous intent and bounded executed action history. Pin the chat template with `enable_thinking=False` and greedy decoding. Save the actual input token IDs, first-hit and stop events, and cold and warm timings.

For assigned-intent execution, keep the same `h=(effects,preserve)` until a verified hit, failed or unknown preservation, task or episode completion, or the per-intent primitive limit. Begin with 12 executed primitives. Record `intent_timeout` at this limit and `budget_cutoff` if a shared limit stops the attempt earlier. A speculative attempt uses a copy of the frontier state and memory and charges its work to the shared budget. A live timeout leaves the controller at its actual endpoint with the latest memory and remaining budget. Record the effects of live movement, resource changes and death in the continuing state.

Keep the original source attempt and native replay alongside every hindsight label. Codex sees only a public task, endpoint observations and the typed vocabulary. Verify `h_prime` on the complete selected prefix, including every preservation check. Retain the earliest verified hit and the selected endpoint. Admitted labels use the training split and record the original assigned `h` in their lineage. Their observed offsets describe behavior under that original request. Directed measurements require new trials explicitly requesting `h_prime`.

Freeze candidate identities, input hashes and verified training lineage before the Prompt 05 directed trials. Bind the versioned pool hash to the campaign ledger. Use a future pool version for corrections or additional candidates. Keep controlled integration traces outside the pool. Predeclared scripted rollouts on frozen train-support groups may supply checked demonstration labels, with scripted provenance preserved.

Bind every directed block to the checked support data, held-out training groups, candidate instantiations, frozen policy and initial memory. Compare candidates from the same physical snapshot. Use one verified deterministic trial or two distinct native future keys for stochastic execution. Count semantically completed attempts, including failures, in the denominator. Preserve interrupted and undispatched slots with separate statuses. Refill the original slot and seed when a later reservation permits it. Report descriptive counts for incomplete pools and assign comparative scale only when the whole context is measured and at least two successful durations differ.

## Budget and handoff

Use one SQLite ledger at `analysis/intent-pilot/campaign.sqlite3`. The ceiling is USD 0 for metered services and 7,200 cumulative local worker-seconds. Reserve 1,800 for Prompt 09. Prompts 01–08 can commit up to 5,400 worker-seconds. Time from concurrent jobs is added. For one job with internal concurrency, declare the maximum number of independent concurrent workers. The wrapper charges its elapsed time for every declared worker. CPU math threads belong to a worker and should be recorded as hardware settings.

Budget each experiment with `scripts.intent_pilot run`. Set `--phase preparation` for data work, warm-up and integration before the measured trial, and `--phase inference` for measured controller execution. Record controller calibration as an inference activity with a distinct name from final evaluation. The ledger reserves the timeout plus a second per worker for startup and cleanup, enforces the command deadline with GNU `timeout`, and charges actual elapsed time. Failed launches, retries and completed timeouts remain separate rows. An unsettled reservation stays committed after an interruption. Check the ledger before issuing a retry.

Keep model downloads, human annotation, Codex annotation and observable Codex usage in separate preparation rows via `record-preparation`. Omit unavailable fields so they appear as null. Run local commands only. There is no Luna, Sol or Astra inference, and no metered provider fallback. A missing weight or incompatible runtime is a preparation dependency.

Every stage begins by reading this file and [STATUS.md](STATUS.md). After doing the work, append the exact tested resume command, frozen inputs, output paths, results and failure counts, remaining budget, and the next prompt. Put generated traces, files, caches and logs under `analysis/intent-pilot/`. The Markdown journal records each handoff. The SQLite ledger supplies the current budget.
