# Luna prompts and verified few-shot examples

The active experiment instructions are in **`configs/icl/experiments/base.json` →
`prompts`**. Every preset in `configs/icl/budget_sweeps/` inherits them. The
fields are:

- `policy`: state + proposed target → probabilities `[UP, DOWN, LEFT, RIGHT]`.
- `value`: current board and goal → discounted continuation estimate.
- `generator`: board and task → complete explicit-board proposals.
- `fixed`, `relative`, `absolute`: additional scale instructions for each method.

The request builder appends the required output schema, board dimensions, scale,
controller cap or discount where applicable. The preview shows the complete
assembled messages, not just these editable pieces.

Create a child JSON using `extends` and override only the `prompts` fields you
want to change. Config inheritance recursively merges objects. `few_shot` controls
the number of examples (default four); `response_format`, `model`, token caps,
retrieval and all budgets are in the same base file. A generator output must
still pass dimension, tile, layout, goal, box-count and player validation; exact
reachability is checked by the simulator during a controller attempt. Never
assume a structurally valid output is reachable.

`custom_generator.example.json` is a runnable example of overriding only the
generator prompt while inheriting the other defaults. It is an illustrative
variant, not part of the matched comparison. Set the demo notebook's `BASE_CONFIG`
to `configs/icl/prompts/custom_generator.example.json` to inspect it; use the
same resolved config deliberately across matched conditions in experiments.

Resolved prompts are embedded in each saved `config.json` and sweep manifest.
Do not put API keys or other secrets in prompt fields; use the ignored `.env`.
Changing the **policy** prompt or policy examples changes the frozen-policy
fingerprint, requiring calibration for that exact policy before relative search.
Changing generator/value prompts does not change policy calibration, but any code
or condition change invalidates a running sweep's resume guard. Start a new output
directory instead of mixing conditions. A cached completed API response may be
reused for identical request payloads; choose a new cache directory to force fresh
requests. No model outputs are generated by editing or previewing this file.

## Where the few-shot examples come from

`data/icl/training.json` contains the prepared training contexts. The path to the
original trajectory shard is `trajectory_source` in `ExperimentConfig`; its
resolved value and source hash appear in the dataset provenance. `make icl-prepare`
creates the disjoint train/validation/test splits after replaying
training trajectories. The runtime derives, rather than invents:

1. **Generator:** one verified state → later board per selected training context;
   fixed mode uses the requested trajectory offset `k`, while relative mode uses
   success-weighted calibration labels `u` for retained targets.
2. **Policy:** state + later target → one-hot probability of the next verified
   trajectory action. Four default examples use requested offsets 1/4/8/16.
3. **Value:** board + task → `discount ** remaining_actions` for the recorded
   successful trajectory (a training target, not measured model accuracy).

The held-out test solution is not included in prompts. The demonstration notebook
replays selected generator examples before showing them and can display every
message by setting `SHOW_ALL_EXAMPLES = True`.

## Preview without API calls

```bash
uv run --extra icl python -m scripts.run_icl_search preview \
  --config configs/icl/budget_sweeps/quick_fixed.json --mock
```

This prints the path to `preview_quick_fixed_12x12x4.json`, containing exact
request payloads and four real few-shot exchanges for each role; it sends no
requests and does not load `.env`. The policy preview uses a training state;
the demo notebook shows the real test-state policy request after generation.
A relative generator preview requires a completed calibration for the selected
provider/policy. `mock` and live calibrations are never interchangeable.
The heuristic mock generator selects a one-step successor and ignores the
requested scale; mock runs cannot validate policy-relative temporal behavior.

For live use, choose `PROVIDER = 'openai'` in
`notebooks/luna_components_demo.ipynb`, select the project Python kernel, and
run from the top. The notebook defaults to mock and does not issue calls until
its clearly labelled inference section. No live output is guaranteed valid;
inspect `physical requests`, `cache hits`, generator diagnostics, the independent
bounded reachability check and the controller trace. `CACHE_DIR` can be set to a
new path to avoid local cached responses. See `ICL_SEARCH.md` for the full
experiment workflow and `configs/icl/budget_sweeps/README.md` for costs.
